# 보고 체계 (Reporting)

> 2단 보고: **① 팀별 보고**(기술, 팀 간 공유해 협업) + **② report_chief**(운영자용, 비개발자 친화 종합).
> 운영자는 report_chief만 읽어도 된다. 팀 보고는 팀끼리 읽고 조율하는 용도.

---

## ① 팀별 보고 — `0_report/teams/YYYY-MM-DD_<팀>.md`
각 기능팀(플랫폼/연동/인프라)이 **자기 진행을 스스로** 올린다. 기술 용어 OK.
**다른 팀도 읽는다** — "다른 팀에 공유·요청" 섹션으로 서로 물려 돌아가게 한다.

형식:
```
# [<팀>] YYYY-MM-DD 팀 보고
## 현황·한 일        — 오늘 무엇을 했나(근거: 파일:라인/로그)
## 막힌 것(blocker)  — 무엇이·왜 막혔나, 결정적 vs 일시적
## 다음 한 동작       — 바로 다음에 할 것
## 다른 팀에 공유·요청 — 교차 의존
```

## ② report_chief — `0_report/report_chief/YYYY-MM-DD.md`
팀장이 팀 보고들을 **종합**해 **운영자용 일일보고**를 만든다. 운영자는 **비개발자** → 아래를 지킨다:
- **쉬운 말**. 코더 용어(함수·RC·커밋해시) 노출 금지.
- **결과·의미 중심**. "무엇을 했다"보다 "그래서 어떤 의미인지".
- 첫 줄에 **"한 줄 요약"**. 표·비유 환영.
- 4개 섹션: **현황 / 계획 / 운영자 지원 필요 / 팀 검토**.

## 흐름
```
각 팀 → 팀 보고 작성(0_report/teams/) ─┐
         ↕ 서로 읽고 조율(공유·요청)     │
팀장 → 종합 → report_chief ─────────────┴──▶ 운영자(이것만 읽음)
```
- 서사·상세는 팀 보고에. report_chief는 **짧고 쉽게**.
- 이 체계는 전역 기본 동작(`~/CLAUDE.md` "지식·문서 관리")의 일부 — 모든 프로젝트에 동일 적용.
